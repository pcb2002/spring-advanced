## Lv 6. AOP API 로깅 및 로그 파일 관리 기록

### 1. [문제 인식 및 정의]

* **문제 상황:** 어드민 권한이 필요한 민감한 API(댓글 삭제, 유저 역할 변경)가 호출될 때, 누가 언제 접근했는지에 대한 기록이 남지 않음.
* **리스크:** 보안 사고나 데이터 오조작 발생 시 원인을 파악할 수 있는 감사 로그(Audit Log)가 부재하며, 콘솔 로그만으로는 서버 재시작 시 데이터가 휘발되어 장기적인 이력 추적이 불가능함.

### 2. [해결 방안]

#### 2-1. [의사결정 과정]

* **AOP(Aspect Oriented Programming) 도입:** 비즈니스 로직에 로깅 코드를 직접 삽입하면 코드의 중복이 발생하고 핵심 로직을 방해함. 따라서 공통 관심사인 로깅을 별도로 분리하여 관리하기 위해 AOP를 선택함.
* **Logback 활용:** 스프링 부트의 기본 로깅 프레임워크인 Logback을 설정하여 콘솔 출력과 동시에 파일 저장이 가능하도록 설계함.

#### 2-2. [해결 과정]

* **어드민 전용 포인트컷 설정:** `CommentAdminController`와 `UserAdminController`의 특정 메서드를 가로채도록 `@Pointcut` 정의.
* **부가 기능(Advice) 구현:** `@Around` 어드바이스를 통해 API 호출 전/후의 시간, 요청자 ID, API 경로 등을 추출하여 로그를 남기는 `AdminAccessLoggingAspect` 클래스 작성.
* **로그 파일 보관 설정:** `logback-spring.xml` 파일을 생성하여 `./logs/admin_access.log` 경로에 로그를 저장하고, 일 단위로 파일을 분리(Rolling)하며 30일이 지난 기록은 자동 삭제하도록 구성.

### 3. [해결 완료]

#### 3-1. [회고]

* **성과:** 비즈니스 로직을 전혀 수정하지 않고도 중요한 API 접근 이력을 확보함. AOP를 활용함으로써 향후 로깅이 필요한 API가 늘어나더라도 포인트컷 설정만으로 손쉽게 확장할 수 있는 구조를 만듦.
* **배운 점:** `JoinPoint`를 통해 런타임 시점에 파라미터나 메서드 정보를 추출하는 방법을 익혔으며, 로깅 설정을 통해 서버 운영의 안정성을 확보하는 경험을 함.

#### 3-2. [전후 데이터 비교]

| 항목 | 작업 전 (Before) | 작업 후 (After) |
| --- | --- | --- |
| **로그 출력** | 표준 출력(Console)만 발생 | 콘솔 출력 + 로컬 파일 저장 |
| **데이터 휘발성** | 서버 재시작 시 로그 소멸 | `./logs/*.log` 파일로 영구 보관 |
| **관리 효율성** | 로그 확인을 위해 터미널 상시 주시 | 날짜별 로그 파일로 사후 추적 가능 |
| **코드 가독성** | 로직과 로깅 혼재 가능성 높음 | AOP 분리로 비즈니스 로직 순수성 유지 |
